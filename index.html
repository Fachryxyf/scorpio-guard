Design notes & implementation · v0 · 2026

Catatan desain & implementasi · v0 · 2026

Trust is a spectrum, not a verdict.

Trust itu spektrum, bukan putusan.

Scorpio Guard is a local, advisory trust-evaluation library for web interactions, sitting on top of an open symptom/prescription protocol. It does not answer human or bot. It estimates how much trust an interaction currently deserves, and hands that judgement back to whoever owns the application.

Scorpio Guard adalah library evaluasi trust yang berjalan lokal dan bersifat advisory untuk interaksi web, di atas protokol symptom/prescription yang terbuka. Ia tidak menjawab manusia atau bot. Ia memperkirakan seberapa besar trust yang layak diberikan pada sebuah interaksi, lalu menyerahkan penilaian itu ke pemilik aplikasi.

PremisePremis

No web behavior is inherently human

Tidak ada perilaku web yang inheren manusiawi

Mouse movement, timing, DOM interaction, navigation order, request intervals — all of it can be recorded, studied and replayed. So chasing a signal that is impossible to forge is chasing something that does not exist.

Gerak mouse, timing, interaksi DOM, urutan navigasi, interval request — semuanya bisa direkam, dipelajari, dan direplikasi. Jadi mencari sinyal yang mustahil dipalsukan sama dengan mencari sesuatu yang tidak ada.

Don't look for the unforgeable signal. Combine weak signals into evidence that is expensive to fake consistently.
Jangan mencari signal yang mustahil dipalsukan. Gabungkan signal lemah menjadi evidence yang mahal untuk dipalsukan secara konsisten.

What follows from that

Konsekuensinya

  • Identity is a history, not a fingerprint.
  • Trust accumulates and decays; it is never permanently fixed by old behavior.
  • Unusual behavior is evidence, not guilt.
  • A new entity is unknown, not untrusted.
  • The goal is asymmetric cost, not perfect detection.
  • Identitas adalah riwayat, bukan sidik jari.
  • Trust bertambah dan meluruh; tidak pernah dipaku permanen oleh perilaku lama.
  • Perilaku tak biasa itu evidence, bukan kesalahan.
  • Entity baru itu unknown, bukan untrusted.
  • Tujuannya asymmetric cost, bukan deteksi sempurna.

Product shapeBentuk produk

A library you install, not a service you call

Library yang dipasang, bukan layanan yang dipanggil

This is not a centralized verification service. There is no client → central service → token → origin round trip on every request. Scorpio Guard is an open-source library installed inside your own ecosystem.

Ini bukan layanan verifikasi terpusat. Tidak ada alur client → layanan pusat → token → origin di setiap request. Scorpio Guard adalah library open source yang dipasang di ekosistem kamu sendiri.

This resolves the apparent tension between "the system must learn" and "the system doesn't report home": learning happens at project level — slow, human-mediated, through issues and reports — not at instance level, fast and automatic per request.

Ini menyelesaikan ketegangan antara "sistem harus belajar" dan "sistem tidak melapor ke pusat": pembelajaran terjadi di level proyek — lambat, lewat manusia, via issue dan laporan — bukan di level instance yang cepat dan otomatis per request.

Zero frictionTanpa friksi

Volume is evidence, not guilt

Volume adalah evidence, bukan guilt

A legitimate user must stay free to search repeatedly, run batch operations, fire large request counts, repeat a workflow, or change habits entirely — without being reclassified as malicious for it.

User legitimate harus tetap bebas melakukan pencarian berulang, operasi batch, request dalam jumlah besar, workflow repetitif, atau berubah kebiasaan total — tanpa otomatis dianggap malicious.

500 requests  !=  bot
500 requests  ==  evidence

context + trust + history + behavioral model
        -> what it actually means

Target: legitimate traffic experiences nothing. Sustained abuse experiences steadily rising operational cost.

Target: trafik legitimate merasakan tidak ada apa-apa. Abuse yang terus-menerus merasakan biaya operasional yang naik terus.

Trust modelModel trust

Trust as a distribution, not a number

Trust sebagai distribusi, bukan angka

Trust is held as a Beta distribution. Positive evidence adds to α, negative evidence adds to β. A brand-new entity starts at Beta(1,1) — flat, uninformative, honest about knowing nothing.

Trust disimpan sebagai distribusi Beta. Evidence positif menambah α, evidence negatif menambah β. Entity yang benar-benar baru mulai di Beta(1,1) — rata, tanpa informasi, jujur bahwa belum tahu apa-apa.

p ~ Beta(alpha, beta)

E[p]   = alpha / (alpha + beta)
Var[p] = (alpha * beta) / ((alpha+beta)^2 * (alpha+beta+1))

new entity -> Beta(1, 1)  ==  unknown, not untrusted

Carrying the variance matters as much as the mean: trust = confidence + uncertainty. Evidence is weighted, so a strong negative and a weak negative do not move the distribution equally.

Membawa variance sama pentingnya dengan mean: trust = confidence + uncertainty. Evidence punya bobot, jadi negatif kuat dan negatif lemah tidak menggeser distribusi sama besar.

Memory & decayMemori & decay

Remember without becoming dogmatic

Mengingat tanpa jadi dogmatis

Human behavior changes. Trust must not become a permanent sentence based on the past, so both parameters decay before new evidence lands.

Perilaku manusia berubah. Trust tidak boleh menjadi hukuman permanen berdasarkan masa lalu, jadi kedua parameter meluruh sebelum evidence baru masuk.

alpha_t = lambda * alpha_(t-1) + positive_evidence
beta_t  = lambda * beta_(t-1)  + negative_evidence

0 < lambda < 1

lambda -> 1   long memory
lambda -> 0   forgets fast

AnomalyAnomali

Trust and anomaly are two different questions

Trust dan anomali itu dua pertanyaan berbeda

Trust

How much do we believe this entity, given its accumulated history?

Seberapa besar kita percaya entity ini, berdasar riwayat yang terkumpul?

Anomaly

Anomali

How strange is this behavior compared to behavior observed so far?

Seberapa aneh perilaku ini dibanding perilaku yang sudah diamati?

Anomaly is a continuous score, not a binary classifier — density estimation, isolation forest, or a Gaussian mixture are all plausible. What it must never do is read anomaly as malicious.

Anomali adalah skor kontinu, bukan classifier biner — density estimation, isolation forest, atau Gaussian mixture semuanya masuk akal. Yang tidak boleh: membaca anomaly sebagai malicious.

trust   = 0.97
anomaly = 0.91
verdict = still plausibly a legitimate batch workflow

ContextKonteks

The same behavior means different things

Perilaku yang sama bisa berarti berbeda

Fifty requests can be a known legitimate batch, or a new identity with low trust hitting a sensitive endpoint in an unusual sequence. The number is identical; the meaning is not.

Lima puluh request bisa berarti batch legitimate yang sudah dikenal, atau identitas baru dengan trust rendah menyerang endpoint sensitif dalam urutan tak biasa. Angkanya sama; artinya tidak.

decision != anomaly_score
decision != trust_score

decision = f(trust, uncertainty, anomaly, context,
             history, velocity, endpoint_sensitivity,
             behavioral_consistency)

Decision layerLapis keputusan

A spectrum, not a switch

Spektrum, bukan saklar

ALLOWOBSERVEINCREASE_FRICTIONRESTRICTBLOCK

When uncertainty is high, observation beats punishment. Each step to the right demands strictly stronger evidence than the one before it, and the final call always belongs to the host application.

Saat uncertainty tinggi, mengamati lebih baik daripada menghukum. Tiap langkah ke kanan menuntut evidence yang lebih kuat dari sebelumnya, dan keputusan akhir tetap milik aplikasi yang memasang.

Epistemic stageTahap epistemik

Lack of evidence is not evidence of distrust

Tidak adanya evidence bukan bukti ketidakpercayaan

A mean of 0.5 has two entirely different causes: nothing has been observed yet, or a great deal has been observed and it genuinely balances. Variance does not separate them, because for a Beta distribution Var[p] = p(1-p)/(n+1) — it already mixes the mean with the amount of evidence.

Nilai tengah 0.5 punya dua sebab yang sama sekali berbeda: belum ada yang diamati, atau sudah banyak diamati dan memang berimbang. Variance tidak memisahkan keduanya, karena untuk distribusi Beta Var[p] = p(1-p)/(n+1) — ia sudah mencampur nilai tengah dengan banyaknya evidence.

So evidence mass is read as its own stage, ahead of trust and uncertainty.

Karena itu massa evidence dibaca sebagai tahap tersendiri, sebelum trust dan uncertainty.

n = alpha + beta

UNKNOWN       n < 3    the trust dimension asks for nothing
DEVELOPING    n < 7    trust begins to influence treatment
ESTABLISHED   n >= 7   the full decision model applies

A first-time visitor is n = 2 — the prior and nothing else — so the trust dimension has no standing to ask for anything, and the advice is to allow. That is not a floor forcing the outcome: a proven constraint violation still reaches the decision layer on its own authority, and a brand-new entity that breaks a declared invariant is still restricted.

Pengunjung pertama kali adalah n = 2 — prior dan tidak ada yang lain — jadi dimensi trust tidak punya dasar untuk meminta apa pun, dan sarannya adalah izinkan. Ini bukan lantai yang memaksa hasil: pelanggaran constraint yang terbukti tetap sampai ke lapis keputusan atas otoritasnya sendiri, dan entity yang benar-benar baru tapi melanggar invariant tetap dibatasi.

Three ceilings apply and the lowest binds — epistemic stage, uncertainty, and whether the anomaly dimension agrees that low variance was earned by varied behavior rather than by volume. Mass decays like everything else, so an entity that goes quiet drifts back to unknown.

Tiga batas berlaku dan yang terendah mengikat — tahap epistemik, uncertainty, dan apakah dimensi anomali setuju bahwa variance rendah didapat dari perilaku beragam, bukan dari volume. Massa ikut meluruh, jadi entity yang diam bergerak kembali ke unknown.

SignalsSinyal

Hard constraints vs weak signals

Hard constraint vs weak signal

These two are not blended into one score. They are typed differently because they fail differently.

Keduanya tidak dilebur jadi satu skor. Keduanya dibedakan tipenya karena cara gagalnya berbeda.

Hard constraints — the skeleton

Hard constraint — kerangka

Physically impossible, not merely unusual. Always on, precise, never learned, never goes stale.

Mustahil secara fisik, bukan cuma tak biasa. Selalu aktif, presisi, tidak dipelajari, tidak pernah kedaluwarsa.

  • A form field filled with zero corresponding interaction
  • Input consistent with direct JS injection, no pointer events at all
  • Event sequences that cannot physically occur in that order
  • Field form terisi tanpa interaksi apa pun
  • Input yang konsisten dengan injeksi JS langsung, tanpa pointer event
  • Urutan event yang secara fisik tidak mungkin terjadi

Weak signals — the flora

Weak signal — flora

Unusual, not impossible. Individually inconclusive, meaningful only in combination.

Tak biasa, bukan mustahil. Sendirian tidak menyimpulkan apa pun, hanya berarti kalau digabung.

  • Actions under ~70ms — a calibrated threshold, not a law
  • Identical patterns repeating over time
  • Randomized delays that are too uniformly random — the tell is the shape of the randomness, not the delay
  • Access windows inconsistent with normal usage
  • Which resource is being requested, and idle actions that should require interaction
  • Aksi di bawah ~70ms — ambang hasil kalibrasi, bukan hukum
  • Pola identik yang berulang terus
  • Delay acak yang terlalu seragam acaknya — tandanya ada di bentuk keacakannya, bukan di delay-nya
  • Jendela akses yang tidak wajar untuk pemakaian normal
  • Resource apa yang diminta, dan aksi idle yang seharusnya butuh interaksi

Weak signals reinforce around the hard constraints instead of firing on their own. That relieves them of carrying full-precision weight, which is where false positives usually come from.

Weak signal memperkuat di sekitar hard constraint, bukan memicu sendiri. Itu melepaskan beban presisi penuh dari mereka, sumber utama false positive.

Symptom flowAlur gejala

Prescription, not diagnosis

Resep, bukan diagnosis

A patient says "I have a headache." That is a category of complaint — a few bytes of information — not a transfer of the headache itself. The library works the same way: when it meets a case it cannot resolve confidently, it sends an abstract symptom; the server returns a prescription; the library acts locally against its own data.

Pasien bilang "saya sakit kepala." Itu kategori keluhan — informasi beberapa byte — bukan pengiriman sakit kepalanya. Library bekerja sama: kalau menemui kasus yang tidak bisa diselesaikan dengan yakin, ia mengirim symptom abstrak; server membalas prescription; library bertindak lokal dengan datanya sendiri.

local application
      |
      |  abstract symptom
      v
prescription server
      |
      |  prescription
      v
  local guard  --  compute / evaluate / decide / act
The prescription travels. The patient does not.
The prescription travels. The patient does not.

Three things fall out of this at once: privacy by architecture rather than by policy, cross-ecosystem learning at pattern level without touching anyone's raw data, and local speed — the round trip only happens for genuinely uncertain cases.

Tiga hal langsung didapat sekaligus: privasi lewat arsitektur bukan lewat kebijakan, pembelajaran lintas ekosistem di level pola tanpa menyentuh data mentah siapa pun, dan kecepatan lokal — round trip hanya terjadi untuk kasus yang benar-benar tidak pasti.

VocabularyKosakata

The symptom vocabulary

Kosakata gejala

Raw behavior is reduced to a standardized token before anything leaves the machine. An instance may not invent symptom names the ecosystem does not know.

Perilaku mentah direduksi jadi token standar sebelum apa pun keluar dari mesin. Sebuah instance tidak boleh mengarang nama symptom yang tidak dikenal ekosistem.

raw behavior -> feature extraction -> symptom abstraction -> standardized symptom

47 requests / 2.3s   ->   SYM_REQUEST_BURST

SYM_REQUEST_BURSTSYM_NEW_BEHAVIORSYM_IDENTITY_DRIFTSYM_UNUSUAL_SEQUENCESYM_HIGH_VELOCITYSYM_UNKNOWN_PATTERN

The vocabulary is versioned (schema v1, v2, …) and structured in two tiers: stable skeleton categories that rarely change, and flexible technical detail underneath. Because the protocol is public, this is now load-bearing infrastructure — it needs the discipline of designing DNS record types or HTTP status codes, not the freedom of an internal enum.

Kosakatanya diberi versi (schema v1, v2, …) dan disusun dua lapis: kategori kerangka yang stabil dan jarang berubah, serta detail teknis yang fleksibel di bawahnya. Karena protokolnya publik, ini jadi infrastruktur penopang — butuh disiplin seperti merancang tipe record DNS atau status code HTTP, bukan kebebasan enum internal.

EncodingEncoding

Why explicit feature values can't be sent

Kenapa nilai fitur eksplisit tidak bisa dikirim

The library is open source, so anything human-readable in its wire format is also readable by the people it defends against. Shipping click_interval=220ms hands an attacker an exact target to route around.

Library-nya open source, jadi apa pun yang bisa dibaca manusia di format wire-nya juga bisa dibaca oleh pihak yang mau dihadapi. Mengirim click_interval=220ms berarti memberi penyerang target persis untuk dihindari.

The direction — explicitly a research direction, not a solved design — is a representation decodable only by the server: not merely encrypted in transit, but structured so that no third party, including someone who has read the whole library source, can interpret what it encodes. The library itself may not understand what it is sending.

Arahnya — dan ini eksplisit arah riset, bukan desain yang sudah selesai — adalah representasi yang hanya bisa dibaca server: bukan sekadar terenkripsi saat transit, tapi terstruktur sedemikian sehingga tidak ada pihak ketiga, termasuk yang sudah membaca seluruh source library, bisa menafsirkan isinya. Library-nya sendiri mungkin tidak paham apa yang ia kirim.

Noted for future reference, not evaluated in depth: one-way hashing and embeddings, server-issued transformation recipes distributed at setup, private/unlabeled model embeddings as used in some fraud-detection systems.

Dicatat untuk nanti, belum dievaluasi dalam: hashing dan embedding satu arah, "resep" transformasi terbitan server yang dibagikan saat setup, embedding model privat/tak berlabel seperti di beberapa sistem deteksi fraud.

Local-firstLocal-first

Data stays where the decision happens

Data tetap di tempat keputusan dibuat

application -> local guard -> local observation -> local inference
                                    -> local decision -> local enforcement

After install and provisioning, the guard needs no runtime conversation with any server. It holds its own observations, trust state, behavioral model and context. The server is a source of prescriptions and model distribution — not a brain that validates every request.

Setelah dipasang dan diprovision, guard tidak butuh komunikasi runtime dengan server mana pun. Ia punya observasi, state trust, model perilaku, dan konteksnya sendiri. Server adalah sumber prescription dan distribusi model — bukan otak yang memvalidasi tiap request.

Explicit non-goals

Non-goal eksplisit

  • No mandatory central telemetry
  • No centralized user profiling
  • No runtime request forwarding
  • No hidden behavioral collection
  • Tidak ada telemetri pusat yang wajib
  • Tidak ada profiling user terpusat
  • Tidak ada penerusan request saat runtime
  • Tidak ada pengumpulan perilaku yang disembunyikan

Installing a library does not entitle it to the behavioral data of someone else's users. Privacy is best realized through architecture, not through a privacy policy.

Memasang sebuah library tidak memberinya hak atas data perilaku pengguna orang lain. Privasi sebaiknya diwujudkan lewat arsitektur, bukan lewat privacy policy.

EconomicsEkonomi

Asymmetric cost, not perfect detection

Asymmetric cost, bukan deteksi sempurna

An attacker can imitate one signal. Possibly several. What gets expensive is holding consistency across behavior, history, context, identity, temporal pattern and interaction relationships — all at once, over time.

Penyerang bisa meniru satu sinyal. Mungkin beberapa. Yang jadi mahal adalah menjaga konsistensi lintas perilaku, riwayat, konteks, identitas, pola waktu, dan relasi antar interaksi — semuanya sekaligus, dalam durasi panjang.

legitimate interaction  ->  near-zero friction
abusive automation      ->  increasing cost

AdaptationAdaptasi

No security model gets to be final

Tidak ada model security yang boleh dianggap final

Attackers observe, learn, adapt, then automate. A guard that stops changing loses by default. The question is not whether the guard should evolve, but where the evolution signal comes from.

Penyerang mengamati, belajar, beradaptasi, lalu mengotomasi. Guard yang berhenti berubah kalah dengan sendirinya. Pertanyaannya bukan apakah guard harus berevolusi, tapi dari mana sinyal evolusinya datang.

attacker:  observe -> learn -> adapt -> automate
guard:     observe -> learn -> adapt -> release

It does not come from harvesting every user's behavior into a central store. It comes from the software side: issues, pull requests, false-positive reports, abuse reports, benchmarks, security research. The maintainer learns from feedback about the software, not from the behavioral data of other people's users.

Sinyalnya tidak datang dari mengumpulkan perilaku setiap user ke penyimpanan pusat. Ia datang dari sisi software: issue, pull request, laporan false positive, laporan abuse, benchmark, riset keamanan. Maintainer belajar dari umpan balik tentang software-nya, bukan dari data perilaku pengguna orang lain.

Software evolves centrally; trust stays local.
Software berkembang terpusat; trust tetap lokal.

GovernanceTata kelola

Open protocol, replaceable server

Protokol terbuka, server bisa diganti

Open core, stated plainly: the library is open source, and so is the protocol — the symptom format, the prescription structure, the shared vocabulary. Rule content stays private per server implementation, because published rules are rules an attacker can route around.

Open core, terang-terangan: library-nya open source, protokolnya juga — format symptom, struktur prescription, kosakata bersama. Isi aturan tetap privat per implementasi server, karena aturan yang dipublikasikan adalah aturan yang bisa dihindari penyerang.

The reference server is one implementation, not a requirement. Anyone — a company, another community, even a competitor — can run their own against the same protocol. That removes the single point of failure, and lets a compliance-bound organization self-host instead of trusting a third party.

Server referensi adalah satu implementasi, bukan keharusan. Siapa pun — perusahaan, komunitas lain, bahkan kompetitor — bisa menjalankan servernya sendiri dengan protokol yang sama. Itu menghapus single point of failure, dan memungkinkan organisasi yang terikat kepatuhan untuk self-host alih-alih menitipkan kepercayaan ke pihak ketiga.

Precedents for this shape: DNS, SMTP, ActivityPub, Let's Encrypt — an open protocol with one prominent implementation most people default to, without that implementation being structurally required.

Preseden bentuk ini: DNS, SMTP, ActivityPub, Let's Encrypt — protokol terbuka dengan satu implementasi menonjol yang jadi pilihan default, tanpa implementasi itu wajib secara struktural.

What is open, what is not, and what that costs

Apa yang terbuka, apa yang tidak, dan berapa harganya

The intent is not 100% open source, and pretending otherwise would be dishonest. The split, stated plainly:

Niatnya bukan 100% open source, dan berpura-pura sebaliknya tidak jujur. Pembagiannya, terang-terangan:

Open core has known failure modes, and this project has not solved them yet. Naming them is part of the design:

Open core punya mode kegagalan yang sudah dikenal, dan proyek ini belum menyelesaikannya. Menyebutkannya adalah bagian dari desain:

Contributor incentive mismatch
Insentif kontributor tidak sejalan
Work contributed to the open library can feel like value flowing into a closed server. Governance has to say early what stays open forever, and why the rest does not.
Kontribusi ke library terbuka bisa terasa seperti nilai yang mengalir ke server tertutup. Tata kelola harus menyatakan sejak awal apa yang terbuka selamanya, dan kenapa sisanya tidak.
Cost concentration
Biaya menumpuk di satu titik
Reference-server load scales with library adoption, on one person, with no cost model decided yet.
Beban server referensi tumbuh seiring adopsi library, di satu orang, tanpa model biaya yang sudah diputuskan.
Blurred debugging responsibility
Tanggung jawab debug jadi kabur
On a false positive, the community can only inspect the library, even when the root cause is a bad prescription. There needs to be a way to report "this smells server-side" without exposing server internals.
Saat false positive, komunitas cuma bisa memeriksa library, padahal akarnya bisa prescription yang buruk. Harus ada cara melaporkan "ini kelihatannya dari server" tanpa membuka isi server.

The replaceable-server model in the previous section is what keeps the first failure mode — a single maintainer as the ecosystem's only brain — from being fatal.

Model server yang bisa diganti di bagian sebelumnya adalah yang membuat mode kegagalan pertama — satu maintainer sebagai satu-satunya otak ekosistem — tidak jadi fatal.

QuickstartMulai cepat

First evaluation in four steps

Evaluasi pertama dalam empat langkah

Start observational. The guard advises; it never acts. Record what it would have said next to what your existing defences actually did, and only then consider wiring the advice to behavior.

Mulai dari observasi. Guard menyarankan; ia tidak pernah bertindak. Catat apa yang akan disarankannya di samping apa yang benar-benar dilakukan pertahanan yang sudah ada, baru setelah itu pertimbangkan menyambungkan sarannya ke perilaku.

1 · Declare what is impossible in your flow

1 · Deklarasikan apa yang mustahil di alur kamu

Declaring hard asserts the edge set is complete for that scope. If you cannot enumerate it honestly, declare soft and it contributes evidence instead of proof.

Mendeklarasikan hard berarti menyatakan himpunan edge-nya lengkap untuk scope itu. Kalau tidak bisa didaftar dengan jujur, deklarasikan soft supaya ia menyumbang evidence, bukan bukti.

import { createGuard, transitionGraph } from '@fachryxyf/scorpio-guard';

const checkoutOrder = transitionGraph({
  id: 'checkout-order',
  scope: 'checkout',
  strength: 'hard',
  allowed: [
    { from: 'cart', to: 'address' },
    { from: 'address', to: 'payment' },
  ],
});

2 · Create one guard, once

2 · Buat satu guard, sekali saja

Create it at module scope, not per request: the default store lives in the guard, so a new guard per request is a new empty history per request.

Buat di scope modul, bukan per request: store default hidup di dalam guard, jadi guard baru tiap request berarti riwayat kosong baru tiap request.

const guard = createGuard({ invariants: [checkoutOrder] });

3 · Evaluate an interaction

3 · Evaluasi sebuah interaksi

entity is any stable reference you already have — a session id, an account id, a signed cookie. The guard never interprets it and never treats it as proof of identity.

entity adalah referensi stabil apa pun yang sudah kamu punya — id sesi, id akun, cookie bertanda tangan. Guard tidak pernah menafsirkannya dan tidak pernah menganggapnya bukti identitas.

const result = await guard.evaluate({
  entity: sessionId,
  observation: {
    scope: 'checkout',
    data: { from: 'cart', to: 'payment' },
    evidence: { positive: 'weak' },
  },
  context: { endpoint: '/pay' },
});

4 · Read the advice, and log the trace

4 · Baca sarannya, dan catat jejaknya

result.decision        // 'RESTRICT'
result.trust.stage     // 'unknown' | 'developing' | 'established'
result.hardViolated    // true when a proof, not a probability, decided this
result.coldStart       // true when no retained state existed
result.trace           // why, in the order that decided it

Log trace from the first day. With four independent dimensions feeding one outcome, an unexplained decision cannot be debugged after the fact — which is why the trace is part of the return value rather than a debug flag.

Catat trace sejak hari pertama. Dengan empat dimensi independen menyatu jadi satu hasil, keputusan tanpa penjelasan tidak bisa didebug belakangan — karena itu jejaknya bagian dari nilai kembalian, bukan flag debug.

A first-time entity is advised ALLOW with stage unknown. That is deliberate: lack of evidence is not negative evidence. A brand-new entity that breaks a hard invariant is still restricted.

Entity yang pertama kali datang disarankan ALLOW dengan tahap unknown. Itu disengaja: tidak adanya evidence bukan evidence negatif. Entity yang benar-benar baru tapi melanggar invariant hard tetap dibatasi.

Honour a deletion request

Penuhi permintaan penghapusan

Behavioral history is personal data under GDPR and Indonesia’s UU PDP. The purge primitive exists from the start; consent and the legal basis remain the host’s responsibility.

Riwayat perilaku adalah data pribadi menurut GDPR dan UU PDP. Primitif purge ada sejak awal; consent dan dasar hukumnya tetap tanggung jawab host.

await guard.forget(entity); // same code path retention uses, horizon forced to zero

Collect interaction in the browser

Kumpulkan interaksi di browser

Counts pointer events, keystrokes, injected input and time-to-submit. Never which keys, never the value. Call stop() on unmount — a collector that outlives its element is a leak.

Menghitung event pointer, ketukan tombol, input yang disuntikkan, dan waktu sampai submit. Tidak pernah tombol apa, tidak pernah isinya. Panggil stop() saat unmount — collector yang hidup lebih lama dari elemennya adalah kebocoran.

import { watchInteraction, toObservation } from '@fachryxyf/scorpio-guard/collect';

const watch = watchInteraction(input, { hasValue: () => input.value.length > 0 });
form.addEventListener('submit', () => {
  send(toObservation(watch.counts())); // { fieldPopulated, interactions, injected, durationMs }
  watch.stop();
});

A populated field with zero interactions is the impossible-idle-action pattern. Declare it soft, not hard: password managers and autofill produce the same shape.

Field terisi dengan nol interaksi adalah pola impossible-idle-action. Deklarasikan soft, bukan hard: password manager dan autofill menghasilkan bentuk yang sama.

Survive more than one process

Bertahan lebih dari satu proses

The default store is process-local, so it resets on restart and is not shared across instances. On serverless that means every cold start is a cold start for trust too — which the guard reports rather than hides, as coldStart: true. Move to a shared store, and prove it against the contract before trusting it.

Store default bersifat process-local, jadi ia reset saat restart dan tidak dibagi antar instance. Di serverless itu berarti setiap cold start juga cold start bagi trust — yang dilaporkan guard, bukan disembunyikan, sebagai coldStart: true. Pindah ke store bersama, dan buktikan terhadap kontraknya sebelum dipercaya.

Hit a false positive? Report it with the trace — a decision without its trace cannot be diagnosed. Found something exploitable? Report it privately instead.

Kena false positive? Laporkan beserta jejaknya — keputusan tanpa jejak tidak bisa didiagnosis. Menemukan yang bisa dieksploitasi? Laporkan secara privat saja.

The libraryLibrary-nya

What is actually built

Apa yang benar-benar sudah dibangun

The model exists as TypeScript with no platform dependencies: Beta-Bernoulli trust, half-life decay over real elapsed time, retention, the decision bands with their ceilings, declared invariants, and the anomaly feature space. One hundred and five tests, most of which exist to pin a number the design argues for.

Modelnya sudah ada sebagai TypeScript tanpa ketergantungan platform: trust Beta-Bernoulli, decay half-life atas waktu nyata, retensi, band keputusan beserta batasnya, invariant terdeklarasi, dan ruang fitur anomali. Seratus lima test, sebagian besar ada untuk memaku angka yang didebatkan desain ini.

const guard = createGuard({ invariants: [checkoutOrder] });

const result = await guard.evaluate({
  entity: sessionId,
  observation: { scope: 'checkout', data: { from: 'cart', to: 'payment' } },
});

result.decision       // 'RESTRICT' - advice, never enforcement
result.trust.stage    // 'unknown' | 'developing' | 'established'
result.trace          // why, in the order that decided it

Every evaluation returns its own reasoning. With four independent dimensions feeding one treatment, an unexplained outcome cannot be debugged by whoever adopted it — so the trace is part of the contract, not a debug flag.

Setiap evaluasi mengembalikan alasannya sendiri. Dengan empat dimensi independen menyatu jadi satu treatment, hasil tanpa penjelasan tidak bisa didebug oleh yang memasangnya — jadi jejaknya bagian dari kontrak, bukan flag debug.

Alongside the core there is a browser-side collector, imported separately as @fachryxyf/scorpio-guard/collect. It counts interaction — pointer events, keystrokes, injected input, time to submit — and records nothing about content, because the impossible-idle-action constraint needs to know whether interaction happened, not what it contained.

Di samping core ada collector sisi browser, diimpor terpisah sebagai @fachryxyf/scorpio-guard/collect. Ia menghitung interaksi — event pointer, ketukan tombol, input yang disuntikkan, waktu sampai submit — dan tidak mencatat apa pun soal isinya, karena constraint impossible-idle-action perlu tahu apakah interaksi terjadi, bukan isinya apa.

Not built: an anomaly classifier over the feature space, and the prescription client. Both wait on decisions recorded in the design log rather than on effort.

Belum dibangun: classifier anomali di atas ruang fitur, dan prescription client. Keduanya menunggu keputusan yang tercatat di log desain, bukan menunggu tenaga.

State storePenyimpanan state

The store contract ships as runnable checks

Kontrak store dikirim sebagai pemeriksaan yang bisa dijalankan

Trust state lives behind a small pluggable interface — read, write, delete for one opaque entity key — with an in-memory implementation as the default and the reference. Anyone can put it in Redis, Postgres, or a durable object instead.

State trust berada di belakang interface kecil yang bisa diganti — baca, tulis, hapus untuk satu kunci entity yang opaque — dengan implementasi in-memory sebagai default sekaligus rujukan. Siapa pun bisa memindahkannya ke Redis, Postgres, atau durable object.

import { checkStoreConformance, assertConformant } from '@fachryxyf/scorpio-guard';

assertConformant(await checkStoreConformance(() => myRedisStore()));

Eleven assertions, no framework, because a store that is subtly wrong produces a guard that is subtly wrong and silent. Three of the checks exist because the mistakes are ordinary, not hypothetical:

Sebelas asersi, tanpa framework, karena store yang salah sedikit menghasilkan guard yang salah sedikit dan diam. Tiga pemeriksaan ada karena kesalahannya biasa terjadi, bukan hipotetis:

Millisecond precision
Presisi milidetik
A second-resolution timestamp column is an ordinary schema choice, and it corrupts both half-life decay and retention invisibly.
Kolom timestamp beresolusi detik adalah pilihan skema yang biasa, dan ia merusak decay half-life sekaligus retensi tanpa terlihat.
The observation window
Jendela observasi
Persisting only the scalar columns is an easy omission, and it disables the entire anomaly dimension with no error raised.
Menyimpan hanya kolom skalar adalah kelalaian yang mudah terjadi, dan ia mematikan seluruh dimensi anomali tanpa error apa pun.
Opaque keys
Kunci opaque
Trimming or lower-casing a key looks harmless and silently merges two distinct entities into one history.
Memangkas atau meng-lowercase kunci terlihat tidak berbahaya, tapi diam-diam menggabungkan dua entity berbeda jadi satu riwayat.

Each failure mode is covered by a deliberately broken store in the test suite, so the kit is shown to catch the mistake rather than merely to describe it. It earned that on its first run: the reference in-memory store handed back the live stored object, so a caller could mutate trust state without going through a write. Frozen now.

Setiap mode kegagalan diuji dengan store yang sengaja dibuat salah di test suite, jadi kit ini terbukti menangkap kesalahannya, bukan cuma menjelaskannya. Ia membuktikan diri pada jalan pertama: store in-memory rujukan mengembalikan objek tersimpan yang hidup, sehingga pemanggil bisa memutasi state trust tanpa lewat penulisan. Sekarang dibekukan.

First integrationIntegrasi pertama

Run against a real flow, changing nothing

Dijalankan pada alur nyata, tanpa mengubah apa pun

The first target is an existing personal health app with a PIN-gated vault, chosen because it already carries hand-rolled defences: a three-strike lockout kept in localStorage, and IP rate limiting in a map that resets whenever the serverless function cold-starts. The comparison is against what a competent developer actually ships under time pressure.

Target pertamanya adalah aplikasi kesehatan pribadi dengan vault berpagar PIN, dipilih karena sudah punya pertahanan buatan tangan: lockout tiga kali salah yang disimpan di localStorage, dan rate limit IP di map yang reset setiap fungsi serverless cold start. Pembandingnya adalah apa yang developer kompeten benar-benar kirim di bawah tekanan waktu.

The guard observes and records; it changes no behavior. Removing the existing defences before there is evidence would destroy both the comparison and the app's protection at once.

Guard mengamati dan mencatat; ia tidak mengubah perilaku. Mencabut pertahanan yang ada sebelum ada bukti akan menghancurkan pembandingnya sekaligus proteksi aplikasinya.

What this does not establish

Yang belum dibuktikan

The finding above came from the declared-invariant layer, which is the least novel part of the design — set membership, expressible as one if. The parts that are actually new describe behavior over populations and over time: trust as a distribution, half-life decay, the epistemic stage, the diversity signal. One person unlocking an app a few times a day cannot move any of them into a regime where they matter.

Temuan di atas datang dari lapis invariant terdeklarasi, bagian yang paling tidak baru dari desain ini — keanggotaan himpunan, bisa ditulis satu if. Bagian yang benar-benar baru menggambarkan perilaku lintas populasi dan lintas waktu: trust sebagai distribusi, decay half-life, tahap epistemik, sinyal diversity. Satu orang membuka aplikasi beberapa kali sehari tidak bisa menggerakkan satu pun dari itu ke wilayah di mana mereka berarti.

So this is a smoke test, not a validated thesis. No threshold is calibrated by it, and the saturation guard cannot be tested without a patient adversary. A target that could settle the question needs unauthenticated traffic, data worth scraping, and a public lookup whose legitimate order can be declared.

Jadi ini smoke test, bukan tesis yang tervalidasi. Tidak ada ambang yang terkalibrasi darinya, dan saturation guard tidak bisa diuji tanpa penyerang yang sabar. Target yang bisa menuntaskan pertanyaannya butuh trafik tanpa autentikasi, data yang layak diambil, dan pencarian publik yang urutan sahnya bisa dideklarasikan.

What happens next, in order

Yang berikutnya, berurutan

The first three items are done: the core model, the store contract, and one observational integration against a real flow. What remains, in order:

Tiga hal pertama sudah selesai: model core, kontrak store, dan satu integrasi observasional pada alur nyata. Yang tersisa, berurutan:

  1. Find an integration target that can actually exercise the statistical layer — unauthenticated traffic, data worth scraping, a real adversary. Nothing below is worth much before this.
  2. Enumerate the known hard constraints exhaustively — the current list is a starting set, not a complete one.
  3. Enumerate known weak signals and how they combine into observe / restrict / block tiers.
  4. Pick an anomaly algorithm over the settled feature space, once there is traffic to choose it against.
  5. Draft the two-tier symptom vocabulary as a concrete v0.1 spec.
  6. Only then investigate encoding schemes for symptom transmission.
  1. Cari target integrasi yang benar-benar bisa menggerakkan lapis statistiknya — trafik tanpa autentikasi, data yang layak di-scrape, penyerang nyata. Tanpa ini, semua di bawah tak banyak berarti.
  2. Daftar hard constraint yang sudah diketahui secara lengkap — daftar sekarang baru titik awal, belum utuh.
  3. Daftar weak signal yang diketahui dan bagaimana kombinasinya jadi tingkat observe / restrict / block.
  4. Pilih algoritma anomali di atas ruang fitur yang sudah disepakati, begitu ada trafik untuk memilihnya.
  5. Susun kosakata gejala dua lapis sebagai spesifikasi v0.1 yang konkret.
  6. Baru setelah itu, teliti skema encoding untuk pengiriman symptom.

What the guard actually claims

Apa yang sebenarnya diklaim guard

It never says "I know you are human." It says: based on the evidence I hold, I trust you enough to let you work.

Ia tidak pernah bilang "saya tahu kamu manusia." Ia bilang: berdasarkan evidence yang saya punya, saya cukup percaya untuk membiarkanmu bekerja.

observe -> remember -> forget -> adapt -> decide
Make legitimate behavior cheap, make abuse expensive, and make security invisible to the people who deserve to use the system.
Buat perilaku legitimate jadi murah, buat abuse jadi mahal, dan buat security tak terlihat oleh orang-orang yang memang berhak memakai sistemnya.
The application owns the data.
The Guard owns the interpretation.
The API distributes the prescription.
The prescription travels; the patient does not.
